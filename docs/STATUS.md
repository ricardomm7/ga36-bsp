Config bases: `sunxi_defconfig`/`A33-OLinuXino` with fex rail values
(DCDC1/2/3/5 = 3.3/1.1/1.26/1.35 V). DRAM is forced to the factory values
(552 MHz, ZQ 63351) with timing parameters and mode registers extracted from
the stock boot0 (`patches/uboot/0008`), PLL5 forced (`0007`), and size
autodetect disabled. The factory eGON header carries `dram_clk=552`,
`dram_zq=0xf777`, `mr0=0x1a50`, `mr1=0x4`, `mr2=0x10`, `mr3=0x0`,
`tpr0=0x2ab83def`, `tpr1=0x18082356`, `tpr2=0x34156` — the SPL mirrors
those values exactly (this is the configuration that produced 2 blinks).

Build: **single entry point** `./build.sh` (bootstrap once with `./bootstrap.sh`).
It runs `build-uboot.sh` → `build-linux.sh` → `build-initramfs.sh` →
`package-final.sh` → `package-stock.sh` (the last is skipped with a warning
if `original/test.img` is absent). Artifacts land in `output/firmware/`.

The old partition layout is forensic evidence only; `scripts/fw/package-final.sh`
owns the new image layout.

## Beacon protocol

The GA36-MB has no accessible UART on this revision, so boot progress is
signalled by blinking the LCD backlight (LED1 on PH00, powered by AXP22x
DC1SW). Implemented in `board/sunxi/board.c` (`ga36_beacon()`,
`patches/uboot/0009`). Every pattern is `n` blinks of 200 ms followed by a 2 s
pause; the pause makes consecutive patterns readable by eye.

## Verification rule (this session onward)

Static analysis (disassembly, file reads, offset math) proves the **file**
is correct — never that the **hardware** ran it. A fix is a *hypothesis*
until a hardware test changes the observable pattern. If hardware behavior
does not change for a fix that should have changed it, record that as a FACT
("fix untested on silicon, or not the cause"), and verify the delivery chain
(build → file → physical card) before opening new hypotheses. Flash
verification: `scripts/fw/verify-flash.ps1` (read back the card and compare
LBA 16 / LBA 80 / full hash).

| Blinks | Meaning | Where it is emitted |
|---|---|---|
| 2 | SPL: DRAM init OK | `sunxi_board_init()`, right after `sunxi_dram_init()` (confirmed on silicon) |
| 3 | SPL: SoC init done, about to load U-Boot from SD | end of `sunxi_board_init()` (after `clock_set_pll1()`) |
| 4 | SPL: U-Boot loaded from SD, about to jump to U-Boot proper | `spl_board_prepare_for_boot()` override in `board.c` |
| 5 | U-Boot proper loaded: `board_init()` reached | `board_init()` (SPL→U-Boot transition, DM up) |
| 6 | U-Boot proper init sequence complete | `misc_init_r()` (console/env/MMC up, just before booting) |
| 7 | reserved: DSI PHY / TCON clock up | to be wired in the DSI driver |
| 8 | reserved: panel reset deasserted | to be wired in the DSI driver |
| 9 | reserved: DCS init sequence sent | to be wired in the DSI driver |
| continuous 100 ms blink | reached the step but failed | e.g. SPL DRAM size = 0 (`sunxi_board_init()` before `hang()`) |

Reading a boot: `2` alone = SPL alive, DRAM OK, stalled before/while loading
U-Boot from SD. `2,3` = SPL SoC init done, stall during SD load of U-Boot.
`2,3,4` = SPL done and jumped, stall in U-Boot proper before `board_init()`.
`2,3,4,5` = SPL→U-Boot transition OK, stall inside `board_init()`. `2,3,4,5,6`
= U-Boot fully up and about to boot the kernel. Nothing then steady glow/hang =
stalled earlier than the first checkpoint.

Note: the beacon build adds ~10 s of deliberate delay per boot (200 ms × blinks
+ 2 s pause per checkpoint). It is a bring-up aid only; drop
`CONFIG_GA36_BACKLIGHT_BEACON` for shipping images.
